# v1.6.0-han.3

## Summary

- Base upstream version: 1.6.0
- Target image: `hanops/ezbookkeeping:v1.6.0-han.3`
- Target platform: `linux/amd64`
- Release source branch: `dev`
- Release commit: `8585b6e1c`

## Fork Features (vs upstream 1.6.0)

Cumulative personal additions on top of upstream:

- Transaction text recognition — import from clipboard, LLM recognizes and pre-fills transaction, available on both mobile (Quick Add page) and desktop (hover menu)
- Full locale support for text recognition (19 languages)
- Independent LLM config for text recognition (`[llm_text_recognition]` section, separate from image recognition)
- Docker frontend build fixes for git-rev-sync
- Personal fork workflow: local smoke test, release notes template, progress tracker
- .gitignore and .dockerignore alignment

## Changes Since v1.6.0-han.2

### Features

- Separate text recognition LLM config from image recognition: independent `[llm_text_recognition]` section, `transaction_from_ai_text_recognition` toggle, and `llmtr` server setting
- Text recognition and image recognition are fully independent (no cross-fallback)
- Add dedicated feature restriction `CREATE_TRANSACTION_FROM_AI_TEXT_RECOGNITION` (type 18) for text recognition
- Desktop text recognition button always visible (matches mobile behavior, rule-based fallback works without LLM)

### Fixes

- Improve text recognition prompt: add rule 8 to guide LLM on transaction type classification (focus on primary action, disregard contextual financial terms)

### Config

- New `[llm_text_recognition]` INI section with all provider options (openai, anthropic, openrouter, ollama, lm_studio, google_ai)
- New `transaction_from_ai_text_recognition` toggle under `[llm]`
- **Note**: this release adds new optional config. Image-only deployment still works without changes.
